# subdd-aiops

Part of the [subdd](../../README.md) Claude Code marketplace. Generated by `node scripts/catalog.mjs`; do not edit by hand.

Install:

```bash
claude plugin marketplace add mauvies/subdd
claude plugin install subdd-aiops@subdd
```

Build the builders: design agents, skills and workflows, engineer prompts, write evals, and scaffold project-specific AI factories.

## Agents

| Agent | Model | When to use |
|---|---|---|
| `subdd-aiops:agent-architect` | opus | Designs agent systems - which agents, skills, workflows and hooks a project needs, how they divide work and hand off, and which model and tools each gets. Use when planning an AI factory for a project or a multi-agent LLM application. |
| `subdd-aiops:eval-engineer` | opus | Designs and runs evaluations for prompts, agents, skills and LLM features - test sets, graders, rubrics and regression suites. Use before changing a prompt in production or to compare models and prompt versions. |
| `subdd-aiops:llm-app-engineer` | inherit | Builds LLM-powered application features with the Claude API and Agent SDK - tool use, structured outputs, RAG, streaming, agent loops, prompt caching, cost and latency control. Use when the product itself needs AI capabilities. |
| `subdd-aiops:prompt-engineer` | opus | Prompt engineer. Writes and improves system prompts, agent instructions, skill descriptions and LLM prompts in applications; diagnoses why a prompt misbehaves. Use when creating or tuning any prompt. |
| `subdd-aiops:skill-author` | inherit | Writes Claude Code skills, workflow skills, subagent definitions and hooks in the correct format, following subdd conventions. Use to create or refactor any agent, skill, workflow or hook file. |

## Workflows (you run them)

| Command | Arguments | What it does |
|---|---|---|
| `/subdd-aiops:diagnose-session` | `[session id, or empty for the current session] [what went wrong]` | Work out what went wrong in a Claude Code session with the subdd plugins - a skill or agent that fired when it should not, stayed silent, ignored the plan or burned tokens - with evidence from the transcript. |
| `/subdd-aiops:eval` | `<target prompt/agent/feature> [variant to compare]` | Build or run an eval suite for a prompt, skill, agent or LLM feature and compare variants. |
| `/subdd-aiops:new-agent` | `<what the agent should do> [--project \| --plugin <plugin-name>]` | Create a new subagent definition (project-local or in an subdd plugin) with the right tools, model and prompt. |
| `/subdd-aiops:new-factory` | `[project path] [short description of the project and its goals]` | Scaffold a project-specific AI factory - analyze the repo, pick plugins and stack pack, generate CLAUDE.md, settings, and project-specific agents, skills and workflows. |
| `/subdd-aiops:new-skill` | `<knowledge or procedure to capture> [--project \| --plugin <plugin-name>]` | Create a new knowledge skill (model-invoked) with a description that triggers correctly and optional supporting files. |
| `/subdd-aiops:new-workflow` | `<process to automate> [--project \| --plugin <plugin-name>]` | Create a new user-invoked workflow skill that orchestrates agents and skills through steps and approval gates. |
| `/subdd-aiops:promote` | `<path to .claude/agents/x.md or .claude/skills/x> [user \| <path to marketplace repo>]` | Promote a project-local agent, skill or workflow from the current repo's .claude/ so other projects can reuse it - to your user-level ~/.claude/ or into a plugin of a marketplace repo you maintain. |

## Skills (Claude loads them when relevant)

| Skill | When it applies |
|---|---|
| `agent-design-patterns` | Patterns for multi-agent and agentic workflow design - pipelines, orchestrator-workers, routing, parallelization, evaluator-optimizer, human gates. Use when designing how agents collaborate or structuring an agentic workflow. |
| `claude-code-extensibility` | Reference for Claude Code extension formats - subagents, skills, workflow skills, hooks, MCP, plugins and marketplaces - and when to use each. Use when creating, editing or choosing between agents, skills, commands, hooks or plugins. |
| `eval-design` | How to design evaluation suites for prompts, agents and LLM features - datasets, graders, rubrics, metrics and regression tracking. Use when testing or comparing prompts, models or agents. |
| `llm-app-patterns` | Architecture patterns for LLM-powered product features - structured output, tool use, RAG, agents, streaming, caching, cost and safety. Use when designing or implementing AI features inside an application. |
| `prompt-engineering` | Principles and checklist for writing system prompts, agent instructions, skill descriptions and in-app LLM prompts. Use when writing or debugging any prompt. |
